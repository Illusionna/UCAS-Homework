# 简易 DNS 解析器

## 项目描述

编写一个能“迭代查询”的 DNS 解析器，不依赖系统的 `gethostbyname` 调用：
- 从一个“根服务器提示文件”（Root Hints）开始
- 向根服务器查询，获取 TLD 服务器地址
- 向 TLD 服务器查询，获取权威 DNS 服务器地址
- 向权威服务器查询，最终获取 A 记录（IPv4 地址）
- 实现一个简单的缓存来存储中间结果

## 实现目的

理解 DNS 这一互联网核心基础设施的查询过程

## 实验拓扑

```text
		     nat0
			  |
			  |
			  |   10.0.0.2
h1 ---------- s1 ---------- h2
```

## 实验流程

- 在 h2 的 xterm 中，运行所实现的 DNS 服务器程序，监听 53 号端口，启动 wireshark 抓包程序，捕获 DNS 相关数据包
- 在 h1 的 xterm 中，分别执行以下命令：
	- `nslookup www.baidu.com 10.0.0.2`
	- `nslookup nonexistent-domain.net 10.0.0.2`
	- `nslookup www.baidu.com 10.0.0.2`
- 结合 h2 的抓包分析：第一次 DNS 请求解析成功，第二次 DNS 请求解析失败，第三次 DNS 解析请求是从本地缓存返回

# TCP 性能分析

## 项目描述

在 Mininet 环境中，设置服务器和客户端之间的带宽为 10Mbps，服务器分别使用 3 种不同拥塞控制算法（reno / cubic / bbr），客户端请求服务器的某个大文件，在服务器侧使用 wireshark 或 tcpdump 抓取文件下载过程中的流量包，然后分析：
- 绘制吞吐量随时间变化的图表
- 绘制 TCP 拥塞窗口值随时间变化的图表
- 识别并统计重传和重复 ACK
- 分析 RTT 的变化
- 将上述信息关联起来，分析拥塞控制算法是如何增长或降低拥塞窗口值的

## 实验目标

通过分析 TCP 拥塞值的变化情况，理解对应的拥塞控制机制

## 拓扑结构

```text
				   10Mbps
				  10ms 延迟
h1 ---------- r1 ---------- h2
				 队列长度 100
```

## 实验流程

1. 在 h1 发送方的 xterm 中：
	- 设置拥塞控制算法 `sysctl -w net.ipv4.tcp_congestion_control=reno`
	- 启动抓包 `tcpdump -i h1-eth0 -w reno_capture.pcap`
2. 在 h2 接收方的 xterm 中启动 iperf 服务器，等待接收数据 `iperf -s`
3. 在 h1 的 xterm 中启动 iperf 客户端，持续发送 30 秒的数据 `iperf -c 10.0.0.2 -t 30`
4. 实验结束后，停止 h1 上的 tcpdump
5. 将抓包文件 reno_capture.pcap 复制出来，进行数据分析
6. 重复以上步骤，更换拥塞控制算法 cubic、bbr 并重新命名抓包文件

# 基于 UDP 的可靠数据传输

## 项目描述

在 UDP 之上实现一个你自己的简单可靠传输协议：
- 序列号 SEQ 来保证顺序
- 确认 ACK 来保证送达
- 超时重传机制
- 简单的流量控制（滑动窗口机制、接收窗口调整）

## 实验目的

掌握传输控制中可靠传输和流控机制

## 拓扑结构

```text
				    10Mbps
				   20ms 延迟
				    5% 丢包
h1 ----------- r1 ----------- h2
```

## 实验流程

- 在 h1 的 xterm 中，运行你实现的 RDT 程序的服务器模式，用于接收数据
- 在 h2 的 xterm 中，运行你实现的 RDT 程序的客户端模式，用于向服务器发送数据（譬如一个 10MB 左右大小的文件）
- 观察你的 RDT 协议是否能正确处理丢包，使用 md5sum 验证文件是否完整有序地送达
- 计算平均传输速率与可用带宽（10Mbps）有多大差距

# 简易 HTTP 1.1 Web 服务器

## 项目描述

基于 TCP Sockets，从零开始实现一个简单的 HTTP/1.1 Web 服务器，监听 8080 端口，能够解析 HTTP 请求并响应，对于接收的请求：
- 如果当前目录存在所请求的文件，返回状态码 200，以及所请求的文件
- 如果所请求的为部分内容（请求中有 Range 字段），返回状态码 206，以及相应的部分内容
- 如果当前目录没有所请求的文件，返回状态码 404

## 实验目的

理解 HTTP 协议的底层工作原理

## 实验拓扑

```text
				  10.0.0.2
h1 ---------- s1 ---------- h2
```

## 实验流程

- 在 h2 服务器的 xterm 中准备一个 index.html 文件，运行所实现的 HTTP 服务器程序，监听端口号 8080
- 在 h1 客户端的 xterm 中，使用 curl 向 h2 发起请求
    - curl [http://10.0.0.2:8080/index.html](http://10.0.0.2:8080/index.html)
    - curl -r start-end [http://10.0.0.2:8080/index.html](http://10.0.0.2:8080/index.html) -o part.html
    - curl [http://10.0.0.2:8080/nonexistent.html](http://10.0.0.2:8080/nonexistent.html)
- 检查 h1 是否成功获取了相应的内容（完整文件、部分文件、404 代码）
